# Decentralized swarm benchmarks and embodied precursor

Reviewed 9 September 2026. These are explicitly swarm-focused sources; their setting is decentralized collective behavior, rather than role-based workflow orchestration.

## SwarmBench: strong operational definition of a swarm

[Ruan et al., *Benchmarking LLMs’ Swarm Intelligence*, arXiv:2505.04364v4, 15 October 2025](https://arxiv.org/abs/2505.04364v4) evaluates agents with local grid observations and locally visible messages, without a planning leader. Five tasks exercise pursuit, synchronization, foraging, flocking, and cooperative transport. Thirteen models were evaluated zero-shot with 5×5 views; reported scores average five runs. No model dominates across tasks. Critically, messages can strongly predict immediate actions without producing strong group-level performance: the paper uses a random-forest action predictor and permutation importance for the former, while reporting weak correlations between communication-content measures and task success for the latter. Those are predictive/correlational analyses, not causal proof. Protocol convergence can correlate negatively with complex-task success; increasing agent count or perception is not uniformly beneficial. Failure patterns include local information silos, overcrowding, repeated exploration, and insufficient coordinated motion. This is directly relevant to swarm communication: **influencing another agent and improving collective accomplishment are different outcomes**. Spatial simulations do not establish scientific-discovery performance.

Code verification: [environment.py](../repositories/RUC-GSAI__YuLan-SwarmIntell/swarmbench/environment.py), `get_agent_visible_messages()` at line 134 filters messages through visibility checks; `get_view()` at line 226 constructs the bounded observation. This substantiates actual informational decentralization. [eval.py](../repositories/RUC-GSAI__YuLan-SwarmIntell/eval.py) invokes `SwarmFramework.submit` with configurable agent count, map dimensions, view size, task, and random seed; the checked-in sample selects two tasks and two seeds, so running its defaults does **not** reproduce the complete paper evaluation. [agent.py](../repositories/RUC-GSAI__YuLan-SwarmIntell/swarmbench/agent.py), `gen_prompt()` at line 47, builds the local sensory/message history; default memory is five frames.

## LLM2Swarm: bringing common-sense inference into local agents

[Strobel, Dorigo, and Fritz, *LLM2Swarm*, arXiv:2410.11387v3, 30 October 2024](https://arxiv.org/abs/2410.11387v3) distinguishes indirect controller synthesis from direct robot-specific LLM inference during deployment. Its ARGoS showcases combine sensor observations with inter-robot natural-language reports. Agents estimate environmental crop/weed proportions, infer motion faults from unchanging coordinates, recognize a peer’s anomalous readings by comparison, and request human help for an unexpected injured-person observation. These are small conceptual demonstrations, not validated scaling results. They illustrate a relevant knowledge mechanism: comparing independent observations exposes a fault that a lone sensor may not identify. The proposed architecture advocates on-device inference, but simulation and preliminary Raspberry Pi tests should not be presented as a deployed fully autonomous hardware swarm. The paper explicitly flags computational, communication, and partitioning limits.

Code verification changes the interpretation: [DirectIntegration/controllers/main.py](../repositories/Pold87__LLM2Swarm/DirectIntegration/controllers/main.py), `controlstep()` at line 186, periodically collects readings and constructs per-robot prompts. Lines 267–275 read **every robot’s previous-round output** from shared files, rather than enforcing SwarmBench-style local communication. [openai-api.py](../repositories/Pold87__LLM2Swarm/DirectIntegration/controllers/openai-api.py), `main()` at line 6, uses the OpenAI client and `gpt-4o`. Thus the available demonstration has robot-specific reasoning but globally exchanged simulated reports and remote inference; “each robot runs its own local LLM” describes the proposed end-state more strongly than this default implementation supports.

Together these sources mark a useful evolution: first demonstrate semantic anomaly inference across robot reports; then explicitly constrain who can perceive and hear whom, and measure whether local influence actually creates collective coordination. For the user’s research, SwarmBench offers the clearer strict-swarm evaluation template, while LLM2Swarm provides an early observation-comparison mechanism for surfacing otherwise hidden conditions.
